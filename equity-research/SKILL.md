# 上市公司基本面研究与估值分析

帮长期投资者独立研究上市公司：输入一家公司，产出**标准化、可验证、可复盘**的研究报告。

核心链路：**数据 → 计算 → 分析 → 判断 → 结论**。严禁：观点 → 猜测 → 买入建议。

## 硬边界

- 只做中长期基本面研究。不预测短期股价，不输出"买入/卖出/目标价"式投资建议
- 不覆盖 ETF、指数、未上市公司、债券、衍生品——遇到这类输入，说明范围后停止
- 技术指标（K线/MACD/RSI）只可作辅助背景，不得作为结论主要依据
- 每份报告末尾必须附免责声明（固定文案见 references/report-template.md）

## 投资理念：任何分析拆成两个独立问题

1. **这是不是一家好公司？**（质量）
2. **现在这个价格值不值得买？**（价格）

好公司 ≠ 好股票。积极结论必须同时满足：**质量达标 + 估值合理 + 足够安全边际**。

不得因股价涨跌、热搜、大V推荐、热门概念改变基本面判断；严格区分"公司价值变化"与"市场价格变化"。

## 数据硬规则（违反任何一条即返工，不交付）

1. 关键数字必须带来源编号 [n]，报告附录给出 URL 与访问时间
2. **禁止使用模型记忆中的财务数据**——记忆只是检索线索，检索验证后才能进报告
3. 找不到的数据写"**数据缺失，无法可靠判断**"；禁止"根据行业情况推测……"
4. 不同来源数据冲突：并列展示 → 解释差异 → 取保守值
5. 禁止编造财务数据、管理层信息、市场份额、估值、股价、新闻、公告
6. **一切数值计算（增长率/ROE/DCF 等）必须用 scripts/ 下的脚本完成，禁止心算**——LLM 手算长数字必然出错，且无法复现
7. 全报告标注【事实】【计算】【判断】【假设】【结论】五类标签；DCF 参数全部标【假设】
8. 写明"数据截至：YYYY-MM-DD"。财报披露窗口：年报≤次年4/30、一季报≤4/30、半年报≤8/31、三季报≤10/31——判断"最新"时必须考虑披露节奏
9. 数据完备率 <70% → 停止，输出"数据不足，无法得出可靠结论"并列出缺失项

## 两种模式

| | 快速筛选 | 深度研究（默认） |
|---|---|---|
| 触发 | "快速看看XX""XX值不值得关注" | "分析XX""XX值不值得长期投资" |
| 数据 | 最新年报/季报关键数+估值快照 | 5～10年财务+公告+行业+同业 |
| 输出 | 一页纸（report-template.md §B） | 完整报告（report-template.md §A） |
| 结论 | 🟢/🟡/🔴+一句话理由+是否升级深度研究 | 完整结论+评分+估值区间 |

两种模式遵守同一套数据硬规则。

## 工作流（九步，不得跳步）

### Step 0 标的确认
- 只有公司名 → 检索确认代码与交易所；多家同名/近似 → 列候选请用户确认；无法确认则停止
- 代码归属：6开头→沪市；688→科创板；0/3→深市；4/8→北交所；5位数字→港股；字母→美股（V1 以A股为主；美股/港股说明数据局限后可做简化版）
- A+H 两地上市：默认分析A股主体，附 H/A 折溢价；ST/*ST：正常分析，报告首屏显著标注
- 完成判据：代码、名称、交易所、货币、现价与总市值已确认并记录

### Step 1 数据采集
先读 **references/data-sources.md**（来源分级、采集清单、SOP、降级链），再开始采集。按序跑四件套：
1. `python3 scripts/fetch_quote.py {code}` — 行情/PE/PB/市值快照
2. `python3 scripts/collect_f10.py {SECUCODE} reports/{code}_raw.json` — 12年财务序列（如 `600519.SH`）
3. `python3 scripts/pe_percentile.py {SECUCODE}` — PE/PB 历史分位
4. `python3 scripts/f10_sections.py {CODE}` — 主营构成与十大股东（如 `SH600519`）
搜索/子代理不可用时，其余定性条目按 data-sources.md 降级链直连采集（巨潮年报摘要PDF性价比最高：审计意见/股东质押/分红/季度拆分一次拿齐）。
完成判据：采集清单每项要么有 [n] 来源，要么明确标注"缺失"。

### Step 2 数据核验与落盘
- 统一单位（亿元）、口径（合并报表）、币种；关键科目与一级来源（年报原文）抽样核对 ≥3 项
- 数据写入 `./reports/{code}_{日期}_data.md`，后续步骤只引用该文件，不重复检索
- 完备率 <70% → 停止（见硬规则 9）

### Step 3 指标计算
把财务数据整理成 scripts/examples/financials_example.json 的格式，跑 `python3 scripts/calc.py financials.json`。模型职责：填参数、读结果、写解读，**不手算**。

### Step 4 九大模块分析
读 **references/analysis-modules.md**（模块细则、评分 rubric、一票否决清单），完成 M1–M9。

### Step 5 估值
读 **references/valuation.md**；DCF 用 `python3 scripts/dcf.py params.json`（格式见 examples/dcf_example.json）。输出区间，不输出单点。

### Step 6 反向论证（强制）
- Bear Case：假设未来 5 年表现很差，为什么？≥5 条失败路径，指明最值得警惕的 1 条
- Bull Case：远超预期的可能原因
- 多空对照表 + 回答"目前哪一方证据更充分"

### Step 7 评分与结论
按下方"评分与结论"执行：一票否决检查 → 质量分 → 估值判断 → 结论映射。

### Step 8 报告交付
- 完整报告写入 `./reports/{code}_{YYYYMMDD}.md`（目录不存在则创建；同日重跑加 -2 后缀）
- 聊天中只给摘要卡片：结论、质量分、估值区间 vs 现价、一句话核心理由、最大风险、报告路径
- 报告含免责声明、数据截至日、来源附录

长任务控制：分步落盘，后步只读前步产物；年报 PDF 只读关键章节；不在聊天中倾倒中间数据，每步给一句进度。

## 评分与结论

### 一票否决（先于评分；命中任一 → 🔴，首屏列明原因）
- 审计报告为非标意见（保留/无法表示意见/否定）
- 公司或实控人因财务造假被立案或处罚坐实
- 大股东质押 >50% 叠加资金占用或违规担保
- 资不抵债或面临退市风险警示
- 数据完备率 <70%（此时输出"数据不足"）

### 质量分（"是不是好公司"，不含估值）

| 模块 | 权重 |
|---|---:|
| 商业模式 | 15% |
| 行业前景 | 15% |
| 财务质量 | 25% |
| 成长性 | 15% |
| 护城河 | 20% |
| 管理层与治理 | 10% |

各模块 1–10 分（评分锚点见 references/analysis-modules.md，打分必须锚定事实），加权 ×10 为百分制。
等级：≥85 优秀；75–84 良好；60–74 一般；50–59 较弱；<50 差。

### 估值判断（"这个价格值不值得买"）
安全边际 = 1 − 现价 / 内在价值中枢：
≥30% 明显低估｜10%~30% 合理偏低｜−10%~10% 合理｜−30%~−10% 偏高｜<−30% 明显高估。
必须与 PE/PB 历史分位交叉验证，矛盾时取更保守者。

### 结论映射

| 条件 | 结论 |
|---|---|
| 无否决，质量分≥75，安全边际≥20% | 🟢 值得深入研究 |
| 无否决，质量分≥75，安全边际<20% | 🟡 值得关注/等待更好价格 |
| 无否决，质量分60–74 | 🟡（写明短板；显著低估可备注观察点） |
| 无否决，质量分<60 | 🔴 暂不值得投资 |
| 命中否决 | 🔴（首屏列明原因） |

结论必须回答：为什么、最大风险、什么情况会推翻当前判断。

## 脚本

| 脚本 | 用途 |
|---|---|
| scripts/fetch_quote.py | A股行情/PE/PB/市值快照（非官方公开接口，尽力而为，失败改走网页采集） |
| scripts/collect_f10.py | 东财 datacenter 接口拉 12 年财务序列（利润表+资产负债表+现金流量表），输出 calc.py 输入格式：`python3 collect_f10.py 600519.SH out.json` |
| scripts/pe_percentile.py | 拉日频 PE/PB 序列并计算历史分位（5年/全样本）：`python3 pe_percentile.py 600519.SH` |
| scripts/f10_sections.py | 主营构成（产品/行业/地区拆分）+ 十大股东一键采集；内置巨潮公告两步定位函数 |
| scripts/calc.py | 增长/CAGR/利润率/ROE/杜邦/FCF/偿债（输入格式见 examples） |
| scripts/dcf.py | 三情景 DCF + 敏感性矩阵（输入格式见 examples） |
